# Runtime на macOS

Runtime — исполняемое окружение для локальных скриптов или отдельного инструмента. Файлы навыка задают порядок работы. Они не устанавливают Python, браузер, модельный API и системные библиотеки сами по себе.

Используй этот документ после основной установки переносимого профиля. Проверки ниже выполняются на новом Mac. До их выполнения состояние runtime — «не проверено».

Bootstrap этого репозитория переносит разрешённые файлы конфигурации. Он не устанавливает runtime и не выполняет вход в сервисы. Документы и дополнительные профили устанавливаются только при явном выборе пользователя. Перед записью файлов проверь план через `node scripts/bootstrap.mjs --dry-run`; команды запускай из корня репозитория. Способы применения и восстановления смотри в [README.md](../README.md).

## Общий порядок

1. Прочитай `SKILL.md` выбранного навыка и его runtime-справку. Применяй только инструкции нужной задачи.
2. Проверь исполняемые файлы, версии, архитектуру Mac и доступные инструменты Codex. Не переноси Windows-окружения, `.venv`, `node_modules`, браузерные бинарные файлы и абсолютные пути `C:/…`.
3. Установи совместимые зависимости через предусмотренный bootstrap-процесс. Если он требует новый аккаунт, ключ, системное разрешение или лицензию, выполни порядок из [CONNECTIONS.md](CONNECTIONS.md). Запроси у пользователя каждый отсутствующий элемент после проверки текущего состояния.
4. Выполни локальную проверку без изменения пользовательского проекта. Используй временную папку и данные без секретов. Сетевую или платную проверку запускай только в разрешённом объёме.
5. Запиши версию, команду проверки, результат и пределы. Статусы установки, включения, авторизации и проверки веди отдельно.

Успех `--version` подтверждает запуск клиента. Он не подтверждает вход в сервис, готовность всех зависимостей и выполнение задачи.

## Базовые инструменты

Проверь `git --version`, `node --version`, `npm --version`, `uv --version`, `ffmpeg -version` и `ffprobe -version` для компонентов выбранного профиля. Версии и перечень обязательных компонентов берутся из manifest репозитория и выбранного навыка. Не объявляй все перечисленные инструменты обязательными для каждой задачи.

Если интерпретатор Python предоставляет Codex, сначала запроси актуальное окружение через `load_workspace_dependencies`, когда этот инструмент доступен. Не копируй путь из Windows. Для отдельного Python, которым управляет `uv`, используй версию из совместимого контракта навыка и зафиксируй фактически выбранный интерпретатор.

При отсутствии Homebrew или другого требуемого установщика сначала проверь предусмотренный репозиторием способ установки. Не заменяй его случайным установочным скриптом из поиска.

## Возможности, которые предоставляет Codex

Веб-поиск, генерация изображений, браузерные инструменты и связанные с ними API предоставляет текущая установка Codex и подключённые плагины. Клонирование репозитория не копирует эти возможности и права аккаунта.

1. Получи текущий список инструментов и установленных плагинов.
2. Сверь его с задачей. Для документов, таблиц, презентаций и PDF используй навыки установленной версии и `load_workspace_dependencies`, если они этого требуют.
3. Если возможность отсутствует, проверь её доступность в текущей версии, плане и рабочем пространстве. Запроси у пользователя конкретное недостающее подключение или разрешение. Не подменяй отсутствующую функцию вымышленным локальным API.
4. Выполни допустимую безопасную проверку. Для браузера достаточно открыть согласованную несекретную страницу. Генерацию изображения или другую расходуемую операцию не запускай только ради инвентаризации: отметь её непроверенной, пока нет разрешённой задачи.

**Критерий.** Список доступных возможностей проверен. Для каждой отсутствующей возможности записаны причина, запрос пользователю и оставшийся шаг. Наличие навыка `imagegen` само по себе не подтверждает доступ к генератору.

## Papermorph

Papermorph создаёт интерактивные учебные материалы. Локальная адаптация включает русский интерфейс, шаблоны, озвучку и библиотеку SQLite. Сохраняй эту адаптацию при обновлении upstream.

**Источник.** [DozenTwelve/Papermorph](https://github.com/DozenTwelve/Papermorph), исходная версия `093418e1d23026f93fe2b12a7ea203dde5361455`, MIT. Пути и команды Windows из старой runtime-справки требуют адаптации к macOS.

| Задача | Нужные компоненты | Безопасная проверка |
| --- | --- | --- |
| Работа с PDF | `uv`, совместимый Python, `pymupdf` | Импорт `pymupdf`; чтение числа страниц локального тестового PDF без секретов. |
| Озвучка | `edge-tts`, сеть, `ffmpeg`, `ffprobe` | Локальный импорт и версии FFmpeg. Сетевую генерацию голоса проверяй отдельно после согласия на отправку тестового текста. |
| Снимки и проверка страницы | `playwright`, Chromium, `pillow` | Запуск Chromium и снимок локальной тестовой HTML-страницы. |
| Локальная библиотека | Python с SQLite, доступная папка данных | Создание и чтение временной SQLite-базы; постоянную библиотеку не меняй. |

### Подготовка

1. Установи `uv` и нужный Python через согласованный bootstrap.
2. Установи FFmpeg для macOS. Убедись, что `ffmpeg` и `ffprobe` доступны в окружении запуска Codex, а не только в интерактивном терминале.
3. Подготовь Python-зависимости. Пример ниже использует временное окружение `uv`; репозиторий может предоставлять закреплённое окружение.

   ```sh
   uv run --with pymupdf --with edge-tts --with playwright --with pillow python -c "import pymupdf, edge_tts, playwright, PIL, sqlite3; print('imports ok')"
   uv run --with playwright python -m playwright install chromium
   ```

4. Определи абсолютную папку установленного навыка. Прочитай `--help` нужных скриптов перед запуском. Используй существующие `outline.py`, `tts.py`, `shot.py`, `check_blank.py` и `check_volume.py`, когда этого требует задача.
5. Выполни локальные проверки из таблицы. Для `shot.py` и `check_blank.py` подними сервер только на `127.0.0.1` и свободном порту. Выходные файлы сохраняй во временной папке.

**Запрос для озвучки.** «Для проверки Edge TTS нужен сетевой запрос. Разрешите отправить сервису этот несекретный тестовый текст: “[текст]”. Русский голос по умолчанию — `ru-RU-DmitryNeural`».

Edge TTS отправляет текст внешнему сервису. Обычная проверка зависимостей не разрешает отправлять пользовательские документы. При сетевой ошибке сохрани исходный текст, используй уже успешные аудиофрагменты и запиши точный статус.

**Пределы.** PyMuPDF читает имеющийся текстовый слой PDF. Для сканов нужно отдельно подготовить распознанный текст. SQLite хранит локальные данные; она сама не синхронизирует материалы, браузерный прогресс и аккаунты между компьютерами. Копирование навыка не переносит личную библиотеку.

**Критерий.** Импорты, FFmpeg, SQLite и локальный Chromium проверены на Mac. Озвучка имеет отдельный статус: проверена разрешённым сетевым запросом либо не проверена. Полная готовность Papermorph требует проверки именно того сценария, который нужен пользователю.

## Harness2: навык

Обычный навык Harness2 задаёт цикл Propose → Probe → Compose: предложить изменение способа работы, проверить его на задаче и принять полезный результат. Он работает внутри `engineering-control` и использует checkpoint задачи для доказательств и выводов.

Для обычного применения навыка не нужны upstream Python runner, API-ключи модели и отдельный платный запуск. Достаточно установленного навыка, доступных инструментов задачи и локального места для checkpoint.

**Проверка.** Прочитай установленный `SKILL.md` и его ссылки. На текущей разрешённой задаче зафиксируй исходное условие, одну проверяемую гипотезу, фактическую проверку и вывод. Не запускай benchmark только ради подтверждения установки навыка.

**Критерий.** Навык доступен и его порядок применён к разрешённой задаче. Это не доказательство результатов статьи или готовности upstream runner.

## Harness2: upstream benchmark

Это отдельное необязательное окружение. Источник: [google-research/harness2](https://github.com/google-research/harness2), закреплённая версия `1cfe254e8d25b15f37048c3730134686abe60335`, пакет `harness2==0.1.0`, Apache-2.0. Сначала прочитай [SETUP.md этой версии](https://github.com/google-research/harness2/blob/1cfe254e8d25b15f37048c3730134686abe60335/docs/SETUP.md).

**Платформа.** Руководство закреплённой версии требует Linux для benchmark. macOS не считай подтверждённой платформой. Для benchmark подготовь отдельную Linux-машину или совместимую Linux VM/контейнер после проверки требований upstream. Совместимость архитектуры, контейнера и executor нужно доказать отдельно.

На исходной Windows-машине пакет CLI был установлен. Нативный demo завершился ошибкой `ModuleNotFoundError: No module named 'fcntl'`; Linux-среды WSL не было. Это не успешный benchmark и не результат проверки Mac.

### Порядок включения

1. Спроси: «Нужен ли upstream benchmark Harness2? Он требует отдельного Linux-окружения. Обычный навык Harness2 уже можно применять без него».
2. При согласии проверь Linux, архитектуру, Python и зависимости по закреплённому руководству. Выбери отдельную папку результатов. Не меняй системные механизмы блокировок ради обхода ошибки платформы.
3. Для проверки без модельного API можно использовать документированный demo в Linux:

   ```sh
   harness2-demo --output /absolute/task-artifacts/demo --k 2
   ```

4. Перед модельным экспериментом согласуй executor, провайдера, endpoint, модель, новые учётные данные, объём, лимит расходов и разрешение на платные вызовы. Проверь текущие доступы перед каждым запросом недостающего элемента.
5. Прочитай руководство конкретного executor и выбранного benchmark. Запускай только согласованный объём. Сохрани версию исходников, параметры без секретов и фактические результаты.

**Запрос для модельного запуска.** «Для [benchmark] нужен executor [название] и провайдер [название]. Укажите разрешённый endpoint и модель. Создайте учётные данные с нужными правами и введите их локально через защищённый ввод. Подтвердите бюджет [сумма/лимит запросов] и разрешение выполнить [объём] платных вызовов».

Вход в Codex не настраивает этот executor. Не передавай ему сессию Codex и не используй скрытый API приложения. Полный runner ориентирован на JobBench, LAB и WorkBuddy-Bench; он не принимает произвольный frontend-репозиторий как готовый benchmark.

**Критерий.** Для обычного навыка и upstream runner записаны разные статусы. До успешного Linux-запуска runner остаётся непроверенным. Для модельных запусков отдельно зафиксированы согласие, лимит и фактическое выполнение. Оценки качества и ускорения сообщай только по выполненному измерению.

## Blender и Orca

Порядок установки, входа и локальных разрешений приведён в [CONNECTIONS.md](CONNECTIONS.md). Сначала установи совместимый runtime и мост. Затем проверь безопасное чтение состояния. Их наличие в конфигурации не подтверждает, что локальное приложение установлено или слушает нужный порт.

Не переноси значения локальных переменных Orca и настройки сеанса Blender со старого компьютера как готовые учётные данные. Приложение Orca само создаёт свои переменные и служебные файлы на Mac. Для остальных runtime несекретные пути и порты установи заново; секреты вводятся локально через защищённый механизм.
