# Подключения на новом Mac

Этот документ задаёт порядок подключения аккаунтов, MCP-серверов и разрешений macOS. Установка файлов не переносит доступ к сервисам. Проверяй подключения в текущем сеансе нового Mac.

## Порядок работы агента

1. Получи список доступных плагинов, MCP-инструментов и поддерживаемых способов входа. Используй инструменты установленной версии Codex. При необходимости прочитай актуальные инструкции её плагинов.
2. Проверь каждое подключение из таблицы ниже. Начни с проверки состояния подключения. Если её нет, выполни минимальный запрос только на чтение.
3. Для каждого отсутствующего аккаунта, учётного секрета или разрешения явно обратись к пользователю. Не пропускай подключение молча. Можно объединить найденные пробелы в один список. Для необязательного сервиса спроси, подключать ли его сейчас.
4. Попроси пользователя пройти вход через браузер, если сервис поддерживает OAuth. Пользователь сам выбирает аккаунт и подтверждает доступ. После возврата в Codex повтори проверку.
5. Если нужен API-ключ, запроси выпуск нового ключа с минимальными правами для нужной операции. Пользователь вводит его через защищённый интерфейс сервиса, локальное хранилище секретов или скрытый ввод. Проверь только наличие и работоспособность секрета.
6. Запиши результат по четырём независимым признакам. Добавь дату проверки, безопасное имя проверенного ресурса и оставшийся шаг. Не записывай секреты, заголовки авторизации и содержимое аккаунта.
7. Заверши настройку только после учёта всех строк выбранного профиля. Неподключённый сервис должен иметь явный статус: ожидает пользователя, отклонён пользователем или не нужен по его решению.

Перед каждым запросом к пользователю проверь, не появился ли доступ в текущем сеансе. Успешный вход в одном интерфейсе не доказывает вход в другом. Например, плагин GitHub и `gh` могут использовать разные способы авторизации.

## Четыре признака состояния

| Признак | Критерий |
| --- | --- |
| Установлено | Нужный плагин, клиент или локальный пакет присутствует на Mac. Для встроенной возможности Codex это отдельная отметка: «предоставляет Codex». |
| Включено | Возможность разрешена в текущем профиле. MCP-сервер зарегистрирован и доступен сеансу; локальный процесс запущен, если он нужен. |
| Авторизовано | Проверка состояния или запрос к защищённому ресурсу подтверждает доступ выбранного аккаунта. Наличие URL или имени переменной этого не доказывает. Для локального инструмента без аккаунта: «не требуется». |
| Проверено | Выполнена указанная ниже безопасная проверка. Записаны её результат и пределы. Успех на Windows не считается проверкой на Mac. |

Используй значения «да», «нет», «не проверено» и «не требуется». Не заменяй эти признаки общим словом «работает».

## Правила для секретов

- Используй новый вход на новом Mac. Не переноси пароли, cookies, `auth.json`, браузерные профили и файлы сессий.
- Передавай секрет из защищённого локального хранилища непосредственно процессу, которому он нужен. Не проси пользователя вставлять секрет в чат. Не помещай его в Git, аргументы команд, историю оболочки, снимки экрана и журналы.
- Для API-ключа сначала установи владельца, сервис, назначение, минимальные права и срок действия. Запрашивай права записи только для согласованной операции.
- В публичном репозитории сохраняй только имена переменных и безопасные примеры. Не сохраняй локальные значения, внутренние URL с параметрами авторизации и ответы, содержащие секреты.
- При ошибке авторизации сообщи пользователю безопасный код ошибки и нужное действие. Перед повторным входом проверь, какой аккаунт и какой интерфейс требуют доступа.

## Аккаунты и сервисы

Указания об исходном окружении служат перечнем для переноса. Они не подтверждают доступ на новом Mac. Исходный перечень может устареть; актуальное состояние устанавливает проверка в текущем сеансе.

### Codex и OpenAI

**Проверка.** Проверь вход в приложении Codex через поддерживаемый интерфейс аккаунта. Убедись, что нужный профиль и рабочее пространство доступны. Наличие инструментов проверь по текущему списку возможностей. Обычная авторизация Codex не доказывает наличие API-ключа OpenAI для отдельного приложения.

**Запрос при отсутствии доступа.** «Войдите в Codex на этом Mac через браузер. Выберите аккаунт и рабочее пространство, которые нужны для работы. После входа сообщите, что окно вернулось в приложение».

**API отдельно.** Если согласованный runtime требует OpenAI API, сначала объясни назначение и возможную оплату. Запрос: «Для [runtime] нужен отдельный API-доступ. Подтвердите проект, лимит расходов и разрешение на платные вызовы. Создайте ключ с необходимыми правами и введите его через защищённый локальный ввод».

**Критерий.** Аккаунт виден в приложении; нужные инструменты доступны. API считается проверенным только после отдельной разрешённой проверки.

### GitHub

**Проверка.** Найди плагин GitHub и проверь подключение. Прочитай метаданные `romanssam/agent-environments` или другого явно указанного пользователем репозитория. Публичный репозиторий может читаться без входа: такой ответ подтверждает сеть и инструмент, но не аккаунт. Для проверки аккаунта используй поддерживаемый запрос текущего пользователя или статус подключения. При использовании `gh` отдельно выполни `gh auth status` без вывода токенов.

**Запрос.** «Подключите нужный аккаунт GitHub в плагине Codex через браузер. Нужен доступ к [репозиторий/организация]. Если организация требует SSO, подтвердите его. Для `gh` выполните отдельный браузерный вход, если этот клиент нужен».

**Критерий.** Установлен нужный аккаунт и прочитан согласованный ресурс. Чтение не доказывает право push. Проверка настройки не включает commit, push, создание issue или PR.

### Figma

**Проверка.** Проверь подключение плагина Figma. Прочитай метаданные файла, ссылку на который пользователь уже разрешил использовать. Если безопасной ссылки нет, сначала проверь статус подключения. Не выбирай случайный закрытый файл.

**Запрос.** «Подключите аккаунт Figma через браузер. Дайте этому аккаунту доступ к нужному файлу или команде. Для проверки пришлите ссылку на файл, который можно прочитать».

**Критерий.** Статус подтверждает вход; чтение выбранного файла прошло. Права редактирования отмечай отдельно. Не создавай файл или узлы ради проверки входа.

### Adobe Creative Cloud

**Проверка.** Найди доступные инструменты Adobe и их способ проверки входа. Выполни запрос статуса аккаунта или минимальное чтение доступной библиотеки. Используй инструкции выбранного плагина. Доступность инструмента не подтверждает вход и лицензию на конкретную функцию.

**Запрос.** «Войдите в Adobe Creative Cloud через браузер в плагине Codex. Выберите нужный профиль. Подтвердите, что у аккаунта есть доступ к функции [название]».

**Критерий.** Защищённый запрос чтения успешен. Генерация изображения, изменение облачного файла и платная операция требуют отдельной задачи; для проверки подключения их не запускай.

### ChatGPT Spaces и Pages

**Проверка.** Найди инструменты Spaces/Pages. Проверь аккаунт или получи минимальный список доступных пространств. Если пользователь уже указал Space или Page, прочитай только его метаданные.

**Запрос.** «Подключите аккаунт ChatGPT Spaces/Pages в Codex. Выберите нужное рабочее пространство и дайте доступ к [Space/Page]. Подтвердите завершение входа».

**Критерий.** Нужное пространство или страница читается. Проверка не создаёт и не изменяет страницы, расписания или структуру Space.

### Sites

**Проверка.** Найди инструменты Sites и проверь статус подключения. Если сервис поддерживает чтение списка проектов, получи минимальный список. Если такой операции нет, запиши этот предел и используй подтверждённый статус подключения.

**Запрос.** «Подключите Sites в Codex. Выберите аккаунт и рабочее пространство, где должны храниться сайты. Если нужно проверить существующий проект, укажите его».

**Критерий.** Подтверждён аккаунт; выполнена доступная проверка чтения. Создание проекта, публикация, обновление хостинга и домена не входят в проверку подключения.

### ChatGPT Pets

**Проверка.** Найди плагин Pets. Прочитай список питомцев или состояние активного питомца. Отметь отдельно наличие плагина и доступ к нужному аккаунту.

**Запрос.** «Подключите Pets для нужного аккаунта ChatGPT Work. Разрешите чтение библиотеки питомцев. Подтвердите завершение входа».

**Критерий.** Список или состояние читается. Не активируй, не загружай и не удаляй питомца ради проверки.

### Linear MCP

**Исходный ориентир.** Linear входил в перечень MCP-подключений. Наличие записи MCP не подтверждает рабочий вход.

**Проверка.** Проверь регистрацию и включение MCP. Используй запрос текущего пользователя, рабочих пространств или минимальных метаданных доступной команды. Не публикуй содержимое задач в отчёте.

**Запрос.** «Подключите Linear MCP через поддерживаемый браузерный вход. Выберите нужное рабочее пространство и разрешите чтение команды [название]. Если сервер требует токен, создайте новый токен с минимальными правами и введите его локально через защищённый ввод».

**Критерий.** Прочитано нужное пространство или команда. Создание задачи и комментария не входит в проверку.

### Notion MCP

**Исходный ориентир.** Notion входил в перечень MCP-подключений. На новом Mac нужен новый сеанс.

**Проверка.** Проверь статус MCP и прочитай метаданные согласованной страницы либо сведения о текущем подключении. Доступ интеграции к другим страницам не предполагается.

**Запрос.** «Подключите Notion MCP через браузер. Выберите нужное рабочее пространство и разрешите доступ к странице [ссылка/название]. Для интеграции с токеном введите новый токен через защищённый локальный ввод».

**Критерий.** Выбранная страница читается. Не создавай и не изменяй страницы ради проверки.

Если инструмент возвращает ссылку для подключения, передай её пользователю после проверки, что ссылка не раскрывает секрет.

### project_handbook

**Настройка.** MCP использует bearer-токен из переменной `HANDBOOK_AGENT_TOKEN`. Репозиторий хранит только имя переменной. Значение пользователь создаёт или получает заново и сохраняет на Mac в локальном хранилище секретов. Передавай его серверу через поддерживаемый механизм окружения. Не подменяй bearer-токен случайным ключом другого сервиса.

**Проверка.** Проверь только факт наличия переменной без её значения. Затем выполни чтение метаданных известного пользователю проекта через `handbook_project`. Если проект неизвестен, запроси его идентификатор. Ответ об отсутствии проекта не равен подтверждённому доступу к нужному проекту.

**Запрос.** «Для project_handbook нужен новый действующий bearer-токен. Получите его у владельца сервиса с правами чтения нужного проекта и введите через защищённый локальный ввод как `HANDBOOK_AGENT_TOKEN`. Сообщите безопасный идентификатор проекта для проверки. Сам токен в чат не отправляйте».

**Критерий.** MCP доступен, переменная настроена, метаданные выбранного проекта читаются. Сохранение и отправка пакетов не входят в проверку подключения.

## Локальные приложения и разрешения macOS

### Blender

Blender — локальное приложение. Аккаунт обычно не нужен. Нужны установленная версия Blender, совместимый аддон или MCP-мост и локальное соединение. Используй версию и настройки из проверенного manifest/README моста. Не открывай порт в сеть ради переноса.

**Проверка.** Проверь версию Blender, включение аддона, запущенный мост и чтение сведений о текущей сцене. Не меняй сцену. Если мост не предоставляет чтение, запиши предел проверки.

**Запрос.** «Разрешите установку или включение [аддон/мост] в Blender и запуск его локального сервера. Подтвердите разрешение Blender на локальное соединение, если macOS запросит его».

**Критерий.** Версия зафиксирована; мост отвечает; сведения о сцене прочитаны. Открытие Blender само по себе этого не доказывает.

### Orca

Orca — необязательный локальный runtime. Наличие конфигурации на исходной машине не означает, что его можно запустить на Mac. Сначала проверь совместимость выбранного адаптера и наличие локального приложения.

Приложение может передавать `ORCA_AGENT_HOOK_PORT`, `ORCA_AGENT_HOOK_TOKEN`, `ORCA_PANE_KEY`, `ORCA_TAB_ID`, `ORCA_AGENT_LAUNCH_TOKEN`, `ORCA_WORKTREE_ID`, `ORCA_AGENT_HOOK_ENV` и `ORCA_AGENT_HOOK_VERSION`. Проверяй только наличие имён и документированный контракт установленной версии. Значения создаёт локальное приложение для своего сеанса. Не копируй их с Windows и не проси пользователя вставлять токены. Файл endpoint и hook, которым управляет приложение, также создаётся на новом Mac самим приложением; исходный Windows-скрипт не переноси.

**Запрос.** «Нужен ли Orca на этом Mac? Если да, установите и запустите совместимое приложение, затем откройте агентский сеанс штатным способом. В текущем сеансе отсутствуют [имена параметров]. Приложение должно создать их само. Подтвердите завершение запуска; значения токенов не отправляйте».

**Проверка.** Проверь доступность исполняемого файла, совместимость версии и документированный запрос состояния без изменения проекта. Проверку наличия секретных переменных выполняй без вывода значений. Для каждого внешнего провайдера Orca отдельно проверь аккаунт и разрешения.

**Критерий.** Пользователь выбрал подключение или отказ; при подключении локальная проверка успешна. Непроверенную совместимость отметь явно.

### Доступ к интерфейсу macOS

Запрашивай разрешение для конкретного приложения, которое выполняет действие. Используй актуальный путь в «Системные настройки → Конфиденциальность и безопасность». macOS может потребовать перезапуск приложения.

| Разрешение | Когда требуется | Запрос пользователю | Проверка |
| --- | --- | --- | --- |
| Универсальный доступ / Accessibility | Управление интерфейсом через локальную автоматизацию | «Разрешите [приложение] доступ в разделе “Универсальный доступ”, чтобы выполнять [действие]». | Чтение или безопасный выбор элемента в тестовом окне. |
| Запись экрана / Screen Recording | Снимки экрана или чтение изображения окна | «Разрешите [приложение] запись экрана, чтобы прочитать [окно]. Затем вернитесь в приложение». | Снимок согласованного несекретного окна. |
| Автоматизация / Automation | Управление другим приложением через механизм macOS | «Разрешите [приложение-источник] управлять [приложение-цель] для [действие] в запросе macOS». | Безопасное чтение состояния целевого приложения. |
| Доступ к выбранной папке | macOS блокирует нужный локальный путь | «Разрешите [приложение] доступ к папке [путь] для [действие]». | Чтение согласованного несекретного файла. |

Не расширяй разрешение до полного доступа к диску, если достаточно выбранной папки. Для каждого нового блокирующего запроса macOS сначала проверь текущее разрешение, затем отдельно обратись к пользователю.

### Доверие к hooks

Hooks могут запускать локальные команды. Файлы hooks можно установить, но доверие на новом Mac нужно подтвердить заново.

1. Прочитай установленные hooks и покажи пользователю их назначение и запускаемые команды без секретов.
2. Проверь состояние доверия через поддерживаемый интерфейс установленной версии Codex.
3. Если доверие отсутствует, запроси: «Проверьте команды этих hooks и подтвердите доверие в интерфейсе Codex на этом Mac. После подтверждения я повторю проверку».
4. Проверь сохранённое состояние через этот же интерфейс и, если доступно, безопасный режим проверки hook.

Не переноси и не создавай `trusted_hash` со старого компьютера. Наличие файла hook не означает доверие или успешный запуск.
