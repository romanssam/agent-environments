# Choose the next skill

Use engineering-control's routing table and the current project profile. Identify the requested outcome, what is already known, and the next unresolved step. Read only that step's skill. Execute authorized work; do not stop at recommending a command the agent can perform.

- Concrete change: implement; a bug starts with diagnosing-bugs.
- Consequential product uncertainty: grill-with-docs. Answer repository questions by inspection first.
- Large but understood feature: to-spec → to-tickets → implement per unblocked ticket → code-review.
- Huge effort whose key decisions remain open: wayfinder, then spec/tickets when it becomes implementable.
- Missing profile: setup-matt-pocock-skills. Continuing work: handoff and the saved task checkpoint.
- Domain language: domain-modeling. Module interfaces: codebase-design. Runnable design experiment: prototype.
- Existing reports: triage. Requested architecture survey: improve-codebase-architecture. External primary-source research: research.

Do not load the entire catalog's bodies. Use the direct path for small work and preserve the user's requested scope. Other skills retain their specific triggers and explicit invocation options.

At a phase boundary that needs a context decision, read [PHASE-BOUNDARIES.md](PHASE-BOUNDARIES.md).
